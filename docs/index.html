Buscar tinta en el papiro – user manual

MCSerDeLuz · version 2.2b (2026-11-01). A classical tool that needs no AI. It looks for weak signs of ink in surface-volume segments of the Herculaneum papyrus PHerc. 1447 from the Vesuvius Challenge. It runs on Windows and Linux. The program's windows and reports are in Spanish; this manual is in English.

New in 2.2b: large segments no longer freeze at 88 % (step 6); the progress window keeps responding during the map computation (step 4); the result windows open in about 2–3 s instead of freezing for ~15 s, and they no longer redraw continuously while open. Images, thumbnails and crops show the 60 best candidates by default (configurable; 0 = all); the report and the CSV always list all candidates. Results are identical to 2.2.

Read this first. Herculaneum ink is carbon-based. In X-ray CT its density is almost the same as carbonised papyrus. Everything this tool reports is a weak hint to look at more closely. It is never proof of writing.

1. Install on Windows

Easy way: the one-file .exe

Double-click MCSerDeLuz-buscar-tinta-papiro.exe. You do not need Python. The exe is unsigned, so SmartScreen may show “Windows protected your PC”. Click More info and then Run anyway (on Spanish Windows: Más información → Ejecutar de todas formas). The first start takes a few seconds while the file unpacks itself. The exe is Windows-only.

With Python

winget install Python.Python.3.12          # or python.org, tick "Add python.exe to PATH"
py --version                               # in a NEW PowerShell window
py -m pip install numpy zarr tifffile matplotlib scipy

Then double-click buscar_tinta_papiro.bat, or run py buscar_tinta_papiro.py. The tool runs without scipy, but more slowly.

2. Install on Linux

sudo apt install python3 python3-venv python3-tk        # Fedora: sudo dnf install python3 python3-tkinter
python3 -m venv ~/.venv-buscar-tinta
~/.venv-buscar-tinta/bin/pip install numpy zarr tifffile matplotlib scipy
chmod +x buscar_tinta_papiro.sh
./buscar_tinta_papiro.sh

Keep buscar_tinta_papiro.py and buscar_tinta_papiro.sh in the same folder. The launcher looks for a Python in this order: .venv-buscar-tinta next to the program, then ~/.venv-buscar-tinta, then python3. If none of them has the libraries, it prints these instructions. Without python3-tk you can still use --sin-ventana.

5. Methods

All detection is classical image processing with numpy and scipy. No neural network or ML model is used.

  1. Reading. Only the needed layers are read, chunk by chunk, straight from the zip. A low-resolution level gives a cheap estimate of how much of the segment is papyrus.
  2. Density z-score. A large Gaussian background is subtracted (normalised convolution, so holes do not bleed into the result). The remainder is turned into local z-scores.
  3. Texture. Fibre coherence comes from the Sobel structure tensor, alongside the local standard deviation. Ink tends to break the fibre pattern.
  4. Front minus back. Mean of layers 14–16 minus the mean of layers 17–20. Ink sits on the written surface.
  5. Crackle (optional). A small-scale cracking signal.
  6. These maps are combined into a score. Blobs of stroke size (30–80 px; 1 mm ≈ 115.7 px) are kept. Blobs near segment edges or holes are rejected (distance transform).
  7. Sweep (the an.py thresholds). It uses z > 4 and blob sizes of 25–160 px with area ≥300, at ≥45 px from edges, with voids excluded, over layers 10–21. Segments with less than 5% papyrus are skipped.

6. False-positive controls and classification

Each candidate gets these controls:

  • the per-layer contrast of the blob against its surrounding ring, for layers 10–21;
  • the contrast on the neighbouring sides (layers 10–12 and 19–21);
  • a reverse-depth control: 14–16 minus 10–13, compared with the forward 14–16 minus 17–20;
  • the saturated fraction (≥ p99.5);
  • elongation (structure-tensor eigenvalues);
  • the number of neighbouring candidates within 250 px;
  • the distance to an edge.

Classification rules, applied in this order:

TypeRule
Bright grain / inclusionBright on both neighbouring sides (>1.0), or more than 30% saturated.
Loose specksSeen only in the crackle map, or area <300, or crackle-dominated.
Fibre / layer separationElongation ≥2.5, or seen only in the fibre or inter-layer maps, or the reverse depth is about as strong as the forward depth.
Stroke-like clusterAt least 2 neighbours, the surface is stronger than both sides (+0.5), and forward depth exceeds reverse depth by more than 0.3.
Isolated, unexplainedAnything else (weak).

In the author's sweep of the small PHerc 1447 segments, no stroke-like clusters were found. Most candidates were grains, fibres or specks.

7. Limitations

  • Carbon ink has very low density contrast, so the signal is often below the noise. If the tool finds nothing, that does not mean there is no ink.
  • Segmentation errors, layer separations, mineral grains and fibre crossings can all mimic ink. The controls reduce these false positives but cannot remove them.
  • The thresholds were tuned by hand on a few segments. They are not calibrated against ground truth.
  • Only level-0 surface volumes are analysed. Segments larger than 180 MB are outside the default sweep (see --limite-mb).
  • Results without scipy can differ slightly, because fallback filters are used.

9. Troubleshooting

  • “Falta: numpy…”: install the libraries (section 1 or 2).
  • py is not recognised: install Python, then open a new PowerShell window.
  • No module named tkinter (Linux): run sudo apt install python3-tk, or use --sin-ventana.
  • Out of memory: add --reduccion 2.
  • Very slow or “Not responding” with thousands of candidates: keep Máximo de candidatos at 60 (the default). With 0 (= all) the candidates image can take minutes to draw; the report and CSV list all candidates anyway.
  • Sweep interrupted: run it again and it resumes. Add --rehacer to recompute everything.
